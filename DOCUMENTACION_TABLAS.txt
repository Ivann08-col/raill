DOCUMENTACION COMPLETA - TABLAS, RUTAS Y JSON - PROYECTO SYNAPSE

BASE DE DATOS: synapse_db (MySQL)

================================================================================
TABLA 1: USUARIO
================================================================================
Descripción: Almacena información de usuarios del sistema, autenticación y perfil.

Campos principales:
  - id_usuario: UUID (PK)
  - username: String(100), único
  - correo: String(100), único, requerido para login
  - password: String(255), hasheada con werkzeug
  - nombre_completo: String(200), opcional
  - telefono: String(20), opcional
  - celular: String(15), opcional
  - ubicacion: String(200), opcional
  - fecha_nacimiento: Date, opcional
  - descripcion: Text, opcional
  - avatar_url: String(255), URL de imagen
  - rol_id: Integer (FK -> rol.id)
  - fecha_registro: DateTime
  - ultimo_acceso: DateTime
  - activo: Boolean (default True)
  - preferencias: JSON, opcional

Relaciones:
  - Rol (N:1): cada usuario tiene un rol
  - Tarea (1:N): usuario crea tareas
  - Sesion (1:N): usuario realiza sesiones
  - Progreso (1:N): usuario tiene registro diario de progreso
  - UsuarioSala (1:N): usuario participa en salas
  - RecompensaUsuario (1:N): usuario obtiene recompensas
  - EstadoAnimo (1:N): usuario registra su estado de ánimo

Rutas Backend:
  POST /api/auth/register - Registrar nuevo usuario
  POST /api/auth/login - Login y obtener JWT token
  GET /api/auth/me - Info del usuario actual (requiere JWT)
  PUT /api/auth/me - Actualizar perfil del usuario (requiere JWT)
  POST /api/auth/change-password - Cambiar contraseña
  GET /api/usuarios - Listar todos los usuarios (admin)
  GET /api/usuarios/<id> - Obtener usuario específico
  PUT /api/usuarios/<id> - Actualizar usuario (admin)
  DELETE /api/usuarios/<id> - Eliminar usuario (admin)

JSON Frontend -> Backend (Login):
  {
    "correo": "usuario@email.com",
    "password": "contraseña123"
  }

JSON Frontend -> Backend (Registro):
  {
    "username": "juan_perez",
    "correo": "juan@email.com",
    "password": "segura123"
  }

JSON Backend -> Frontend (Respuesta Login exitosa):
  {
    "access_token": "eyJ0eXAiOiJKV1Q...",
    "usuario": {
      "id_usuario": "uuid-string",
      "username": "juan_perez",
      "correo": "juan@email.com",
      "nombre_completo": "Juan Pérez",
      "avatar_url": "https://...",
      "rol_id": 2,
      "fecha_registro": "2025-01-15T10:30:00"
    }
  }

JSON Backend -> Frontend (GET /auth/me):
  {
    "id_usuario": "uuid-string",
    "username": "juan_perez",
    "correo": "juan@email.com",
    "nombre_completo": "Juan Pérez",
    "telefono": "+1234567890",
    "ubicacion": "Bogotá",
    "descripcion": "Estudiante de ingeniería",
    "avatar_url": "https://...",
    "rol_id": 2,
    "activo": true
  }

Frontend - Ubicación y uso:
  - frontend/src/pages/Login.jsx - Login
  - frontend/src/pages/Register.jsx - Registro
  - frontend/src/pages/Profile.jsx - Ver/editar perfil
  - frontend/src/services/auth.js - Funciones de autenticación
  - frontend/src/services/api.js - Interceptor JWT en headers

TABLA 2: ROL
================================================================================
Descripción: Define los roles/permisos del sistema (usuario, admin, moderador, etc).

Campos principales:
  - id: Integer (PK), autoincrement
  - nombre: String(50), único

Valores predefinidos en BD:
  - 1: admin
  - 2: usuario
  - 3: moderador
  - 4: instructor

Relaciones:
  - Usuario (1:N): múltiples usuarios pueden tener el mismo rol

Rutas Backend:
  GET /api/roles - Listar todos los roles (admin)
  POST /api/roles - Crear nuevo rol (admin)

JSON Backend -> Frontend (GET /roles):
  [
    { "id": 1, "nombre": "admin" },
    { "id": 2, "nombre": "usuario" },
    { "id": 3, "nombre": "moderador" }
  ]

Frontend - Ubicación y uso:
  - Asignación de roles en panel de administración
  - Verificación de permisos con JWT claims

TABLA 3: TAREA
================================================================================
Descripción: Almacena tareas que crean los usuarios para organizar su trabajo.

Campos principales:
  - id_tarea: UUID (PK)
  - usuario_id: UUID (FK -> usuario.id_usuario)
  - sala_id: UUID (FK -> sala.id_sala), opcional (tarea personal o de sala)
  - titulo: String(200), requerido
  - descripcion: Text, opcional
  - estado: String(20) - valores: 'pendiente', 'en_progreso', 'completada'
  - completada: Boolean (default False)
  - prioridad: String(20) - valores: 'baja', 'media', 'alta'
  - fecha_creacion: DateTime
  - fecha_vencimiento: Date, opcional
  - comentario: Text, opcional

Relaciones:
  - Usuario (N:1): cada tarea pertenece a un usuario
  - Sala (N:1): tarea puede estar en una sala (opcional)

Rutas Backend:
  GET /api/tareas - Listar tareas del usuario (requiere JWT)
  GET /api/tareas?estado=pendiente - Filtrar por estado
  GET /api/tareas/<id> - Obtener tarea específica
  POST /api/tareas - Crear nueva tarea
  PUT /api/tareas/<id> - Actualizar tarea
  DELETE /api/tareas/<id> - Eliminar tarea
  PATCH /api/tareas/<id>/completar - Marcar como completada

JSON Frontend -> Backend (POST /tareas):
  {
    "titulo": "Estudiar React",
    "descripcion": "Aprender hooks y context",
    "prioridad": "alta",
    "fecha_vencimiento": "2025-12-31",
    "sala_id": "uuid-sala" (opcional)
  }

JSON Backend -> Frontend (GET /tareas):
  [
    {
      "id_tarea": "uuid",
      "usuario_id": "uuid",
      "titulo": "Estudiar React",
      "descripcion": "Aprender hooks y context",
      "estado": "en_progreso",
      "completada": false,
      "prioridad": "alta",
      "fecha_creacion": "2025-01-15T10:00:00",
      "fecha_vencimiento": "2025-12-31",
      "comentario": null,
      "sala_id": null
    }
  ]

Frontend - Ubicación y uso:
  - frontend/src/pages/Tareas.jsx - CRUD de tareas
  - frontend/src/pages/HomePageLogueado.jsx - Resumen de tareas pendientes
  - frontend/src/services/tareas.jsx - Funciones API para tareas
  - Llamada fetch: api.get('/tareas'), api.post('/tareas', payload), etc.

TABLA 4: SALA
================================================================================
Descripción: Salas de estudio grupal donde usuarios colaboran en sesiones compartidas.

Campos principales:
  - id_sala: UUID (PK)
  - nombre: String(100), requerido
  - descripcion: Text, opcional
  - creador_id: UUID (FK -> usuario.id_usuario)
  - fecha_creacion: DateTime
  - max_participantes: Integer, opcional
  - es_privada: Boolean (default False)
  - codigo_acceso: String(6), opcional (para salas privadas)
  - estado: String(20) - valores: 'activa', 'cerrada'

Relaciones:
  - Usuario (N:1): cada sala tiene un creador
  - UsuarioSala (1:N): múltiples usuarios en una sala
  - SalaSesion (1:N): sesiones realizadas en la sala
  - Tarea (1:N): tareas asociadas a la sala

Rutas Backend:
  GET /api/salas - Listar todas las salas (públicas)
  GET /api/salas/publicas - Listar salas públicas filtradas
  GET /api/salas/mis-salas - Salas del usuario actual
  GET /api/salas/<id> - Obtener sala específica
  POST /api/salas - Crear nueva sala
  PUT /api/salas/<id> - Actualizar sala (solo creador)
  DELETE /api/salas/<id> - Eliminar sala (solo creador)
  POST /api/salas/unirse - Unirse a una sala con código
  POST /api/salas/<id>/salir - Salir de una sala

JSON Frontend -> Backend (POST /salas):
  {
    "nombre": "Estudio Inglés",
    "descripcion": "Sala para practicar inglés",
    "es_privada": false,
    "max_participantes": 10
  }

JSON Backend -> Frontend (GET /salas/publicas):
  [
    {
      "id_sala": "uuid",
      "nombre": "Estudio Inglés",
      "descripcion": "Sala para practicar inglés",
      "creador_id": "uuid",
      "fecha_creacion": "2025-01-10T15:30:00",
      "max_participantes": 10,
      "es_privada": false,
      "codigo_acceso": null,
      "estado": "activa"
    }
  ]

Frontend - Ubicación y uso:
  - frontend/src/pages/Salas.jsx - Listar y crear salas
  - frontend/src/pages/SalaDetalle.jsx - Detalles de sala
  - frontend/src/services/sala.jsx - Funciones API
  - Llamada fetch: api.get('/salas/publicas'), api.post('/salas', payload)

Relaciones:
  - Usuario (N:1): cada sesión pertenece a un usuario
  - Tecnica (N:1): cada sesión usa una técnica
  - SalaSesion (1:N): sesión puede ser grupal en una sala

  GET /api/sesiones - Listar sesiones del usuario

  POST /api/sesiones - Crear nueva sesión

  GET /productividad/pomodoro/estado - Ver estado actual

  POST /bienestar/meditacion/finalizar - Finalizar meditación

TABLA 7: RECOMPENSA
================================================================================
Descripción: Recompensas que usuarios pueden desbloquear acumulando puntos.

Campos principales:
  - id_recompensa: UUID (PK)
  - nombre: String(100), requerido
  - descripcion: Text, opcional
  - puntos_requeridos: Integer
  - tipo: String(50) - valores: 'descuento', 'acceso', 'insignia', 'premium'
  - valor: Integer (porcentaje descuento, días acceso, etc)
  - requisitos: JSON (condiciones para desbloquear)

Recompensas predefinidas (ejemplos):
  - Descuento 10% Premium: 500 puntos
  - Tema oscuro desbloqueado: 200 puntos
  - Insignia Maestro: 1000 puntos

Relaciones:
  - RecompensaUsuario (1:N): usuarios obtienen recompensas

Rutas Backend:
  GET /api/recompensas - Listar todas las recompensas
  GET /api/recompensas/disponibles - Recompensas disponibles para usuario actual
  GET /api/recompensas/mis-recompensas - Recompensas obtenidas del usuario
  GET /api/recompensas/<id> - Obtener recompensa específica
  POST /api/recompensas - Crear nueva recompensa (admin)
  PUT /api/recompensas/<id> - Actualizar recompensa (admin)
  DELETE /api/recompensas/<id> - Eliminar recompensa (admin)
  POST /api/recompensas/otorgar - Otorgar recompensa a usuario

JSON Frontend -> Backend (POST /recompensas/otorgar):
  {
    "recompensa_id": "uuid",
    "usuario_id": "uuid" (opcional, default usuario actual)
  }

JSON Backend -> Frontend (GET /recompensas/disponibles):
  [
    {
      "id_recompensa": "uuid",
      "nombre": "Tema Oscuro",

      "puntos_requeridos": 200,
      "tipo": "acceso",
      "valor": 1,
      "requisitos": { "sesiones_minimas": 10 }
    }
  ]

Frontend - Ubicación y uso:

Campos principales:
  - id: Integer (PK), autoincrement

  - timestamp_inicio: DateTime

Relaciones:
  - Sala (N:1)
  - Sesion (N:1)

Rutas Backend:
  GET /api/salas/<sala_id>/sesiones - Sesiones realizadas en una sala

Frontend - Ubicación y uso:
  - Ver sesiones grupales de una sala
  - Historial de la sala

TABLA 14: MENSAJE_SALA
================================================================================
Descripción: Mensajes de chat en las salas (comunicación entre usuarios).

Campos principales:
  - id_mensaje: UUID (PK)
  - sala_id: UUID (FK -> sala.id_sala)
  - usuario_id: UUID (FK -> usuario.id_usuario)
  - contenido: Text
  - fecha_envio: DateTime
  - editado: Boolean

Relaciones:
  - Sala (N:1)
  - Usuario (N:1)

Rutas Backend:
  GET /api/salas/<sala_id>/mensajes - Listar mensajes de una sala
  POST /api/salas/<sala_id>/mensajes - Enviar mensaje
  PUT /api/salas/<sala_id>/mensajes/<id> - Editar mensaje
  DELETE /api/salas/<sala_id>/mensajes/<id> - Eliminar mensaje

JSON Frontend -> Backend (POST /salas/<sala_id>/mensajes):
  {
    "contenido": "¡Hola a todos!"
  }

JSON Backend -> Frontend (GET /salas/<sala_id>/mensajes):
  [
    {
      "id_mensaje": "uuid",
      "sala_id": "uuid",
      "usuario_id": "uuid",
      "contenido": "¡Hola a todos!",
      "fecha_envio": "2025-01-15T10:30:00",
      "editado": false
    }
  ]

Frontend - Ubicación y uso:
  - frontend/src/pages/SalaDetalle.jsx - Chat de sala
  - Llamada fetch: api.get('/salas/<sala_id>/mensajes')

TABLA 15: PASSWORD_RESET_CODE

Descripción: Códigos temporales para reset de contraseña.

Campos principales:
  - id: Integer (PK)
  - usuario_id: UUID (FK -> usuario.id_usuario)

  - creado_en: DateTime

Relaciones:
  - Usuario (N:1)

Rutas Backend:

  POST /api/auth/verify-reset-code - Verificar código

JSON Frontend -> Backend (POST /auth/request-password-reset):
  {
    "correo": "usuario@email.com"

JSON Frontend -> Backend (POST /auth/reset-password):
  {
    "correo": "usuario@email.com",

  }

Frontend - Ubicación y uso:
  - frontend/src/pages/Login.jsx - Opción "Olvidé contraseña"

FLUJOS PRINCIPALES DEL SISTEMA
================================================================================

FLUJO 1: Registro y Login
1. Usuario POST /auth/register con (username, correo, password)
2. Backend hash password, crea registro Usuario, retorna token JWT
3. Frontend guarda token en localStorage
4. Frontend redirige a dashboard

FLUJO 2: Crear y Completar Tarea
1. Usuario POST /tareas con (titulo, descripcion, prioridad, fecha_vencimiento)
2. Backend crea Tarea, incrementa puntos en Progreso
3. Frontend muestra en lista de tareas
4. Usuario PATCH /tareas/<id>/completar
5. Backend actualiza estado='completada', completada=true, suma puntos

FLUJO 3: Sesión Pomodoro
1. Usuario GET /tecnicas para listar disponibles
2. Usuario POST /productividad/pomodoro/iniciar con (tecnica_id, duracion)
3. Backend crea Sesion con estado='iniciada'
4. Frontend inicia timer local (25 min por defecto)
5. Usuario POST /productividad/pomodoro/finalizar
6. Backend calcula duracion_real, actualiza Progreso, incrementa puntos

FLUJO 4: Meditación
1. Similar a Pomodoro pero con POST /bienestar/meditacion/...
2. Backend registra en Sesion con categoria 'meditacion'

FLUJO 5: Crear Sala y Unirse
1. Usuario POST /salas con (nombre, descripcion, es_privada)
2. Backend crea Sala, agrega creador en UsuarioSala como 'creador'
3. Otros usuarios POST /salas/unirse con codigo_acceso (si es privada)
4. Backend agrega en UsuarioSala como 'participante'
5. Usuarios en sala ven tareas/sesiones compartidas

FLUJO 6: Ganar y Obtener Recompensas
1. Usuario accumula puntos a través de tareas, sesiones
2. Sistema verifica automáticamente requisitos en tabla Recompensa
3. Usuario POST /recompensas/otorgar con recompensa_id
4. Backend crea RecompensaUsuario, deduce puntos, actualiza perfil

FLUJO 7: Registrar Estado de Ánimo
1. Usuario POST /estado-animo con (valor 1-5, nota)
2. Backend crea EstadoAnimo
3. Frontend GET /estado-animo/historial?days=14 para gráfico
4. Backend agrupa por día y calcula promedio

================================================================================
CONSUMO DE JSON - RESUMEN TÉCNICO
================================================================================

Frontend -> Backend (Headers requeridos):
  - Content-Type: application/json
  - Authorization: Bearer <jwt_token> (en todos excepto auth)

Convenciones:
  - UUIDs en formato string "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  - Fechas en ISO 8601: "2025-01-15T10:30:00" o "2025-01-15"
  - Booleanos: true/false (minúsculas)
  - Estados predefinidos: usar strings exactos ('pendiente', 'completada', etc)

Errores Backend (formato estándar):
  {
    "error": "Descripción del error",
    "code": 400/401/403/404/500
  }

Token JWT:
  - Duración típica: 24 horas
  - Incluye: user_id, rol
  - Se envía en header: Authorization: Bearer <token>
  - Se valida con: @jwt_required() en backend

================================================================================
NOTAS DE IMPLEMENTACIÓN
================================================================================

1. Base de datos MySQL con charset utf8mb4 para soporte completo Unicode

2. Todas las queries de GET con JWT validan que el usuario actual sea el propietario
   (excepto admin que puede ver todo)

3. Las fechas se almacenan en UTC en BD, frontend convierte a zona local

4. Los UUIDs se generan con Python uuid.uuid4()

5. Las contraseñas se hashean con werkzeug.security.generate_password_hash

6. Los puntos se calculan automáticamente según tipo de sesión/tarea

7. Las migraciones de BD se manejan con Flask-Migrate/Alembic

8. El JWT expira después de 24 horas, requiere re-login

9. Las salas privadas usan código de 6 caracteres para acceso

10. Los datos sensibles (contraseñas, tokens) nunca se envían en GET/URL
